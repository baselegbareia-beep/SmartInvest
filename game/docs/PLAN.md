# Build plan

The game is built in seven phases. A phase is finished only when its exit check passes. Two commands are part of every exit check: `npm run check` (types, lint, unit tests, build) and `npm run e2e` (the built game in a headless browser).

Machines cannot judge how a game feels in the hand. Six of the seven phases therefore end with a playtest by the owner on their own phone, listed in the last column. Until that playtest is done the phase is "built", not "accepted".

## Phase 0. Design and skeleton
- **Builds:** the project in `game/` (TypeScript strict, Phaser 4.2 pinned, Vite, Vitest, ESLint, Playwright); a title screen that boots; a build that runs from any sub-folder address (relative asset paths); the contract of the simulation (`src/core/types.ts`, `docs/ARCHITECTURE.md`); every feel number (`src/tuning.ts`); the spec, this plan, `docs/ART-AND-SOUND.md` and `docs/LEVELS.md`; a copy of the Phaser 4 skill files (`docs/phaser-skills`) and the verified Phaser 4 recipes (`docs/PHASER4-NOTES.md`); the two development levels as files; the workflow `.github/workflows/game.yml`, which checks every pull request and, on the repository's default branch (today `claude/mobile-financial-charts-SsZsI`; there is no `main`), publishes the existing site with the built game under `/game/`.
- **Exit check:** `npm run check` and `npm run e2e` pass. The e2e test shows that the title boots on WebGL with no console errors and that the page title comes from `src/meta.ts`.
- **Still open:** the workflow has been written and read, but it has never run on GitHub: no pull request exists yet. The first pull request from the work branch runs its `check` job; until that run is green the workflow counts as untested.
- **Owner, no phone needed:**
  1. Read `docs/SPEC.md` and say whether this is the game you want: the name, the theme, the rules.
  2. **Just before the game branch is merged into the default branch (`claude/mobile-financial-charts-SsZsI`, the branch the site is published from today):** in the repository on GitHub open Settings, Pages, and set Source to "GitHub Actions". Today the site is published straight from the branch. If the merge happens first, GitHub publishes the game's unbuilt source under `/game/` (a blank page), and the workflow's own publishing step either fails or competes with it. Make the switch and the merge in one sitting: from the switch until the merge nothing new is published, not even a change to the finance chart, because the default branch has no publishing workflow until the merge brings `.github/workflows/game.yml`. After the merge, every change to the default branch, also one that only touches the finance chart, waits a few minutes for the game's checks (and for the run of the change before it) before the site is published, and is not published if they fail. A failed run is started again from the newest change's run: a run of an older change, started again after a newer one reached the branch, checks but does not publish.
